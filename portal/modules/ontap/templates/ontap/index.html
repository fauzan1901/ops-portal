Restore volume

Site . Restores a LUN from an ONTAP snapshot to a new LUN and volume, then moves it to the target project. The original volume is not changed.

    Volume

    Enter the OpenStack volume ID. In ONTAP the volume appears as LUN volume-<ID>.

    Copy it from the ID column of openstack volume list, or from Horizon.

    Snapshot

    Select the FlexVol snapshot to restore from.

    SelectTimeSnapshot nameSchedule

    Target project

    After cinder manage, the new volume is moved to this project with a volume transfer.

    Leave empty to use the original volume's project.

    Review

    Ansible checks every prerequisite on ONTAP and OpenStack (read-only) before the restore can run.

    Jobs

    Every restore by every user and site, recorded before it runs.

    IDVolumeStatusSiteSnapshotTargetUserStarted

    Approvals

    Original volumes of restores, scheduled for deletion. Nothing is deleted automatically: when a volume is due, an administrator approves the deletion, keeps the volume, or postpones it. The deletion checks the volume again first and never uses --force or --cascade; its Cinder snapshots are deleted first, so Cinder can delete the volume. A volume still attached as a data disk is detached first; a volume that is the boot disk (vda) of an instance can be deleted with that instance (its name typed to confirm): the instance first, then the volume — or, with delete on termination, Nova deletes the volume and the portal checks it is gone.
