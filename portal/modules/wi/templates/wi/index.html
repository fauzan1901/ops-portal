      Hosts & SSH

      The VMs and devices the checks read over SSH, per site and product group, and the SSH credentials they use. A credential that may run fixes lets the button Run this fix run the commands of a check result on its hosts; the others only read. Hosts of sites.yml stay read-only. Keys and passwords are stored encrypted and never shown again (a key is shown by its fingerprint, as ssh-keygen -l prints it). A VM without an address the portal server reaches is added behind a host it does reach (jump host): use Add hosts behind on that host.

      BMC

      The BMC of each server (Lenovo XClarity Controller, Inspur) and the BMC web accounts. The checks read a BMC with the Redfish API over HTTPS on its management IP — the address of its web page — with the same account as the web login (no SSH), and only read (GET): health, power supplies, fans, temperatures, memory, disks and the event log. An account with the read-only role is enough. Passwords are stored encrypted and never shown again; one credential can serve many BMCs.
